# Architecture and repository layout

E is a saturation-based theorem prover for first-order (and, with the `ho`
build, higher-order) logic, written in C99 as a stack of static libraries.
Each library only depends on the ones above it in this list.

| Directory | Prefix | Contents |
|---|---|---|
| `src/basics` | `clb_` | memory management, stacks, trees, hashes, strings, error handling |
| `src/inout` | `cio_` | scanner/parser infrastructure, output, command-line option handling |
| `src/terms` | `cte_` | signature, term cells, term banks (shared terms), substitutions, types, unification (incl. HO) |
| `src/orderings` | `cto_` | term orderings (KBO, LPO) |
| `src/clauses` | `ccl_` | literals, clauses, clause sets, formulas, CNF, rewriting, subsumption, indexing, proof state, derivations |
| `src/propositional` | `cpr_` | propositional clause sets, DPLL |
| `src/learn` | `cle_` | classification, learned-strategy support |
| `src/pcl2` | `pcl_` | PCL2 proof protocol: parsing, checking, analysis |
| `src/heuristics` | `che_` | clause evaluation and selection: weight functions (`WFCB`), literal selection, heuristic definitions, auto-mode (`che_to_autoselect.c`, `che_proofcontrol.c`) |
| `src/control` | `cco_` | the saturation loop and inference control (`cco_proofproc.c`), scheduling, HO inferences |
| `apps/` | | one `.c` file per program (`eprover.c` is the prover), plus `e_options.h`, `e_version.h`; `simple/` and `external/` hold small side programs |
| `third_party/picosat-965` | | vendored PicoSAT |
| `tests/regression` | | deterministic regression suite (see its README) |
| `tests/problems` | | example problems (SMOKETEST, TPTP, LFHOL, ...) |
| `tools/` | | `port_upstream.py` (upstream sync), `development/` and `python/` (old strategy-generation and analysis scripts), `skeletons/` |
| `docs/` | | manual (LaTeX), release notes, contributor list |
| `etc/` | | classification keys, benchpress config, misc tables |

Where heuristics live: clause selection is `che_*` (what gets evaluated, how
clauses are weighted and which literals are selected) and is driven from
`cco_proofproc.c`; the automatic choice of strategy by problem class is in
`che_to_autoselect.c` / `che_proofcontrol.c` and generated by scripts in
`tools/development/`.

## Build, test, sync

* Build: `cmake --preset dev && cmake --build --preset dev -j` (see README.md;
  presets `dev`, `ho`, `fast`, `asan`). Sources are globbed, so new `.c` files
  need no build change.
* Test: `ctest --preset dev`, or `tests/regression/run.py` (see
  `tests/regression/README.md`; exact clause counts are only comparable for the
  same toolchain, use `--status-only` otherwise).
* Style: `tools/format.sh` (pinned clang-format; CI checks it).
* Upstream: this is a fork of `eprover/eprover`; `tools/UPSTREAM_SYNC.md`
  explains how upstream changes are translated into this layout and merged.

## Things to know before changing code

* E orders some data by pointer address. To keep the search reproducible, its
  small objects come from a private arena (`src/basics/clb_memory.c`), hashes
  use ids instead of addresses, and the paramodulation index orders by term id
  and clause creation number. New code should not derive behaviour from
  addresses (no hashing of pointers, no sorting by address where the order can
  matter); `tests/regression/determinism.py` catches regressions. See
  `tests/regression/README.md`.
* Prefer not to touch source files that upstream also changes unless needed;
  it keeps the upstream merge conflict-free.
